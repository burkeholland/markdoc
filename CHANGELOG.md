### Writing

- Undo of a table-menu edit reaches the preview exactly (task #459, follow-up to #437): the binding's minimal replacement used ProseMirror's fitted `tr.replace`, which does not reproduce the parsed document when the text diff starts in one table cell and ends in another row — undoing "add column" left the preview at 4×3 (the header kept its empty cell, `fixTables` padded the bodies) while the Markdown said 4×2, and the two panes stayed apart. When the fitted result differs from the parsed document the whole top-level blocks around the diff are replaced instead (exact, selection in untouched blocks still maps); the table-menu add/remove + undo walk in `e2e/preview-controls.spec.ts` runs unconditionally again and asserts one Ctrl+Z per step.
- First-run onboarding (task #385): the empty dashboard has one primary action, **Start with a guided doc**, which creates a real document from the hidden `welcome` template (`src/lib/templates.ts`, `showInPicker: false`; `GET /api/templates` and the picker list the eight visible ones as before) — *Welcome to Markdoc*, four short sections each ending in something to try (`/` for the block menu, Comment on a selection, Share → Collaborate with an agent), a task list of the three and "Delete this doc when you're done — it's just a doc." A slim **hint bar** under the toolbar (`src/components/editor/hint-bar.tsx`, `aria-live="polite"`, never on phone widths) shows each of three hints once and only when relevant, remembered in `localStorage` `markdoc:hints`: a collaborator and no agent ever seen → Share; a 20+ character selection → Ask an agent; the first comment thread → @-mention Copilot (opens Comments and focuses the composer); ✕ or the action dismisses, and after all three the bar never mounts again. The due-hint logic is pure (`src/lib/hints.ts`, unit-tested); the bar reads the session itself so `EditorShell` still does not re-render per keystroke. **Settings → Agents** opens with a **Set up Copilot CLI** checklist whose checkmarks come from real state: token exists, `tools/list` received over `/api/mcp` (`api_token.last_mcp_seen_at`, migration 0010), a `tools/call` went through or a request was sent from the editor (`last_mcp_call_at`); `/api/tokens` returns both timestamps. `e2e/onboarding.spec.ts`; `a11y.spec` scans the empty state, the hint bar and the checklist.
- Typing in long documents: the incremental re-parse (`src/editor/markdown/incremental.ts`) no longer falls back to a full parse whenever the document contains a footnote or a link-reference definition — the unchanged definitions elsewhere in the document are handed to the region parse, so a keystroke at the end of a 12k-word document re-parses a few lines instead of 86 KB (it still bails out for a definition inside the changed lines, a neighbour definition that an earlier one would shadow, or an unclosed fence at the very end); the idle full-parse verification is a trailing 1 s debounce on `requestIdleCallback`, so it never lands between two keystrokes of a burst; the outline list is memoised on headings + active index instead of the raw caret offset. A 4-char token typed at the end of the Burke-scale document reaches the preview in 259 ms median instead of 1536 ms; `scale.spec` now types where Burke types (`Ctrl+End` into the last paragraph, and mid-document) and records the outside-view token time as well as the per-keystroke median (`d625308`).
- Typing follow-up: the linter reads the binding's incrementally maintained mdast instead of re-parsing the whole document 500 ms after each pause; the editor shell no longer re-renders per keystroke — the caret lives on the collaboration session (outline and panes read it there) and every dialog is memoised with stable handlers, so closed dialogs are not rendered again on each key; `reparseRange` counts line changes inside the edit span only; `scripts/perf-360.mts` measures token latency, React commits per keystroke and a CDP profile of lint and parse; `scale.spec` types one unmeasured warm-up token per caret position before the measured one (600 ms budget for the whole token). End of document 585 → 318 ms, mid-document 456 → 306 ms, per-keystroke medians 14 / 11 ms (`42e7ab2`).

### Accessibility

- Keyboard users can scroll the preview pane of a long document: the ProseMirror content element gets `tabindex="0"` (the same pattern as `.cm-content`), which is what axe's `scrollable-region-focusable` needs on the rich pane's scroll container when the document has no link or checkbox inside it — browsers already tab into `contenteditable`, so this adds no second tab stop; the `preview-rhythm` axe scan covers the whole editor again instead of only the rich pane, and `a11y.spec` adds a 60-paragraph, link-free document at 1280 × 900 that asserts both panes scroll, zero violations light and dark, and exactly one tab stop per pane (`fd93b74`).
- From the Burke-scale scans: the phone outline drawer scrolls (`max-h-full min-h-0` on the aside) instead of growing past the viewport when a document has more than 20 headings; task-list checkboxes carry `aria-label="Task"`; the code pane's content element is `tabindex="0"` so the scrollable `.cm-scroller` has a focusable descendant (`71ab50c`).

REST: `GET /api/agent/requests` (token only), `GET`/`POST /api/documents/:id/requests`, `POST …/requests/:rid/claim`, `…/complete`, `…/cancel`; new `request.done` notification kind and `agent.request` / `agent.request.done` activity rows; `docs/agents.md` has the walkthrough with one example per answer mode (`8f7d246`).
- `markdoc_pull` (`merge?`, `force?`) and `markdoc_sync_status` join `markdoc_publish` (`force?`); all three answer with the sync `status` instead of doing anything destructive (`7d48d33`).
- MCP tools added this day: `markdoc_import_text` (new document from Markdown, plain text or HTML), `react` action on `markdoc_comment`, `markdoc_search_documents`, `markdoc_duplicate_document`, `markdoc_delete_document`, `markdoc_restore_document`; `starred`/`trash` filters on `markdoc_list_documents`; `template` on `markdoc_create_document` (see the entries above).

### Build, ops and tests

- LAN access: the dev server works from a phone or another machine at `http://<your-ip>:3000` or `http://<machine-name>:3000` — Auth.js builds its sign-in, callback and sign-out URLs from the request's `Host` (via the `x-forwarded-*` headers Next derives), so signing in from the LAN no longer bounces to `localhost` or `0.0.0.0` (`AUTH_URL` still wins when set); Next's dev-only cross-origin guard for `/_next/*` is pre-filled with this machine's LAN addresses, hostname and `<hostname>.local` through `allowedDevOrigins` from `scripts/lib/dev-origins.mjs` (`ALLOWED_DEV_ORIGINS=a,b` adds more; restart after a DHCP change); the server binds `0.0.0.0` but no longer hands that to Next as its hostname; the start-up log lists the LAN URLs; `e2e/lan.spec.ts` signs in, edits and reads through a LAN address (`7b33a0b`).
- CI hardening: the stats perf test asserts the **median** of five cold runs against a budget (10 ms locally, 25 ms under `CI`) instead of a single noisy wall-clock sample; the one 15-scan a11y editor test is split into four (split view with panels; floating menus; popovers and dialogs; versions compare and activity) plus the dark scan, so each fits the runner's per-test timeout (`22cde53`).
- Factory paths derive from the repo location (`FACTORY_ROOT`, `scripts/lib/factory-root.mjs`, `Get-FactoryRoot` in `scripts/live/common.ps1`) instead of absolute machine paths; `src/app/confidential.test.ts` fails the run when any word from `CONFIDENTIAL_WORDS` appears in a tracked file (skips when the variable is empty) (`a187c80`).
